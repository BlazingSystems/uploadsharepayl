## Purpose

This repository is reserved for work that begins from an existing open-source/upstream project rather than original BlazingSystems source.

Keeping forks separate makes authorship clear:

- upstream authorship and license stay visible;
- BlazingSystems modifications are documented separately;
- experimental fixes are not misrepresented as original upstream features;
- third-party binaries or assets are not added unless redistribution rights are clear.

## Current Main Branch

No active fork source tree is currently published on `main`. Earlier fork/compatibility work may exist in development history or separate branches, but only reviewed material should be promoted here.

## Folder Standard

Every future fork project folder should contain its own `README.md` with:

1. upstream project and canonical source link;
2. upstream license;
3. exact BlazingSystems changes;
4. build/test status;
5. known failures or compatibility limits;
6. whether the branch is a clean fork, port, patch set or experimental derivative.

## Validation Rule

A failed compile is still useful engineering evidence when documented accurately. Forked work should record the target board/platform, toolchain and failure point instead of hiding unsuccessful attempts.
